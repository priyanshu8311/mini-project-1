# AI Coding Agent Rules & Guidelines (AGENTS.md)

You are an AI coding agent operating within a large, production-grade codebase for the Smart Inventory Management & Demand Forecasting system. 

**CRITICAL DIRECTIVE:** You must strictly follow the rules outlined in this document. Always use `PRD.md`, `DESIGN.md`, `ARCHITECTURE.md`, `DATABASE.md`, and `API.md` as your absolute sources of truth. 

## 1. Golden Rules of Agent Behavior
*   **Inspect Before Modifying:** Always read and analyze existing files, interfaces, and architecture before making any modifications.
*   **No Unrelated Changes:** Never format, refactor, or modify code outside the specific scope of the user's immediate request. 
*   **Follow the Source of Truth:** If a request contradicts the PRD, ARCHITECTURE.md, or DATABASE.md, flag the inconsistency to the user before proceeding.

## 2. Code Quality and Naming
*   **Backend (Python/FastAPI):** Strictly adhere to PEP 8. Use `snake_case` for variables/functions/methods and `PascalCase` for Classes and Pydantic models.
*   **Frontend (React/Next.js):** Use `PascalCase` for components and interfaces, and `camelCase` for functions, hooks, and variables.
*   **Clarity over Cleverness:** Write readable, explicit code. Avoid obscure one-liners.

## 3. Project and Folder Structure
*   Respect the modular monolith structure defined in `ARCHITECTURE.md`.
*   Backend features must be isolated within their specific domain (`/src/domain/inventory`, `/src/domain/users`). Do not cross-contaminate domain logic.
*   Frontend features must utilize the App Router (`/src/app`) and place reusable UI in `/src/components`.

## 4. Component and Pattern Reuse
*   **Frontend:** Always check `/src/components` for existing UI elements (Buttons, Data Tables, Cards, Modals) before creating new ones. Adhere strictly to the Tailwind 8-point grid system and semantic color tokens defined in `DESIGN.md`.
*   **Backend:** Reuse existing SQLAlchemy base models, dependency injections (e.g., Auth), and utility functions. Avoid writing custom logic if a standard framework utility exists.

## 5. Dependency Management
*   **Zero Unnecessary Dependencies:** Do not introduce new `pip` or `npm` packages unless explicitly instructed or absolutely required to fulfill a core PRD requirement. 
*   Leverage the existing stack: FastAPI, SQLAlchemy, React, Tailwind CSS, React Query.

## 6. Type Safety
*   **Backend:** Use strict Python type hints on all functions and methods. Define all request/response schemas and database models using Pydantic and SQLAlchemy 2.0 type mapping.
*   **Frontend:** Strictly use TypeScript. Define interfaces for all component props, API payloads, and state objects. Avoid `any` at all costs.

## 7. Error Handling
*   **Standardized Responses:** Use the exact error JSON structure defined in `API.md`. Do not invent new error formats.
*   **Backend:** Raise appropriate HTTP exceptions (400, 401, 403, 404, 422) for domain violations. Never let an internal server error (500) leak a stack trace to the client.
*   **Frontend:** Use React Error Boundaries and localized toast notifications for API failures (as per `DESIGN.md`). Provide fallback UI for failed components.

## 8. Security and Secrets
*   **NEVER EXPOSE SECRETS:** Never hardcode API keys, passwords, JWT secrets, or database URLs in the codebase.
*   Use environment variables (loaded via `.env`) for all configuration.
*   Respect RBAC: Ensure every newly created endpoint enforces role-based authorization using the established middleware defined in `API.md`.

## 9. Database and API Access
*   **Ledger Pattern:** Never execute a direct `UPDATE` or `DELETE` on inventory totals. You must insert an append-only record into `inventory_transactions` and update `inventory_levels` atomically using pessimistic locking (`SELECT ... FOR UPDATE`), as defined in `DATABASE.md`.
*   **Transactions:** Ensure all multi-table database operations are wrapped in safe, asynchronous database transactions. Roll back entirely on failure.
*   **API Calls:** Use established React Query hooks and custom Axios/Fetch clients for frontend API communication.

## 10. Testing
*   Write tests alongside new features. 
*   **Backend:** Use Pytest. Focus on business logic, math accuracy, and locking mechanisms in the inventory domain.
*   **Frontend:** Use Jest/React Testing Library. Ensure components render correctly, handle loading/error states, and respect accessibility (ARIA) attributes from `DESIGN.md`.

## 11. Documentation
*   Provide concise Google-style docstrings for all Python classes, methods, and complex ML or locking logic.
*   Comment the *why*, not the *what*, for complex algorithmic code.
*   Ensure OpenAPI/Swagger documentation automatically generated by FastAPI is kept accurate by defining robust Pydantic schemas.

## 12. Git and Change Discipline
*   Keep edits atomic. 
*   Do not leave dead code, `console.log`, or debugging `print` statements in the final output.
*   If rewriting an existing function to add a feature, preserve its existing behavior and signature for external dependents.
